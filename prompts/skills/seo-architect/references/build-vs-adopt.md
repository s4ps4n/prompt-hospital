# Build vs adopt для SEO Intelligence Platform

Обязательный проход перед проектированием компонента. Для каждой строки
ниже — либо берём готовое, либо в ADR появляется раздел «почему готовое
не подошло» с конкретной причиной, а не с «нам нужен полный контроль».

## Брать готовое

| Задача из ТЗ | Кандидаты | Почему не своё |
|---|---|---|
| Планировщик и очередь (§22 `scheduler/`) | pg-boss, BullMQ, Temporal | pg-boss живёт в том же Postgres — без отдельного Redis. Своя очередь — это ретраи, идемпотентность, dead-letter и наблюдаемость, месяцы работы мимо продукта |
| Обход сайта (§6) | crawlee | вежливость, конкурентность, дедупликация, robots, ретраи уже решены |
| Парсинг HTML | cheerio, parse5 | — |
| robots / sitemap | robots-parser, sitemapper | форматы полны краевых случаев |
| schema.org, JSON-LD, микроразметка (§6) | готовые экстракторы | стандарт большой, ручной разбор гарантированно неполный |
| Валидация ответов Яндекса (§4, §5) | zod | без схем изменение формата API даёт молчаливые `undefined` в метриках, что хуже падения |
| Векторы и кластеризация запросов (§11.4, §16) | pgvector + агломеративная кластеризация / HDBSCAN | своя мера близости — это research-проект, а не фича |
| Шифрование токенов (§24) | pgcrypto, envelope encryption через KMS | своя криптография — источник тихих дыр |
| HTTP с бэкоффом к API Яндекса | got, undici + p-retry | rate limits и 5xx требуют бэкоффа, а не цикла |
| Генерация отчётов (§20) | шаблонизатор | конкатенация строк не переживёт третьей правки формата |
| Миграции и типы | Prisma | уже в стеке |

## Писать своё — это и есть продукт

- нормализованная модель (§7);
- девять детекторов возможностей (§9);
- приоритизация (§19) — модель, учитывающая спрос, эффект, сложность,
  риск и достоверность;
- контент-планировщик и генерация Content Brief (§10–13);
- workflow Findings → Issues со статусами (§17, §18);
- измерение результата после внедрения (§28).

## Отдельный вопрос: клиенты API Яндекса

Готовых поддерживаемых TypeScript-клиентов Вебмастера и Метрики может не
быть или они могут быть заброшены. Проверять состояние на момент решения,
а не по памяти. Если писать своё — писать тонкий слой поверх HTTP-клиента
и zod-схем, а не «SDK».
