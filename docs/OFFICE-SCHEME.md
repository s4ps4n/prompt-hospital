## Полный путь задачи

### 1. Постановка

Задача попадает в лоток одним из способов:
- `journal.py addTask` — вручную
- `addPlan` — из плана декомпозиции Jev

Поля: `id` (T-N), `title`, `priority`, `kind` (роль), `zone` (область), `dependsOn` (предшественники), `decompose` (флаг разбора).

### 2. Начало тика — выравнивание журнала

```
verify_journal(j)
```

Ловит и лечит рассинхрон «задача ↔ воркер»:
- воркер держит задачу, которой нет в очереди → `unassign`
- задача назначена, но воркер её не держит → `unassign`

### 3. Декомпозиция (если `decompose=true`)

```
op('setDecomposed', [id, 'true'])     ← флаг ДО вызова Jev (защита от дублей)
plan = decompose_request(title, workers)
   ├─ план есть → addPlan (создаёт подзадачи с зависимостями)
   └─ план пуст → setDecomposed false (задача идёт как есть)
```

Jev получает **состав офиса** и не создаёт задачи на роли, которых нет.
По одному плану за тик.

### 4. Фильтрация очереди

Кандидаты: не назначенные, не заблокированные, недекомпозируемые.

### 5. Три фильтра перед назначением

**а) Зависимости** — `deps_ready()`: все предшественники закрыты.
Если нет → `T-N ждёт предшественников: T-M`.

**б) Зона** — `busy_zones`: в одной зоне не работают два воркера.
Если занята → `T-N ждёт освобождения зоны 'X'`.

**в) Свободный воркер** — статус `wait`/`done`, нет задачи, не `w0`.

### 6. Триаж Jev

```
decision = triage_task(task, workers)
→ {'worker_id': 'wN', 'repo': '...', 'confidence': 0.82}
```

Если Jev недоступен — fallback: берём первого свободного.

### 7. Найм (если исполнителя нет)

```
request_staff(role, task, reason) → staffRequest
```

**Автонайма НЕТ** — создаётся заявка `SR-N`, решение принимает владелец.
Затем `release_idle_specialists()` увольняет простаивающих нанятых (кроме ядра: фулстак, приёмщик, дизайнер).

### 8. Выбор рабочей папки

### 9. Тред находок в промпт

```
ПРЕДЫДУЩИЕ НАХОДКИ ПО ЗАДАЧЕ (не повторяй ошибок):
  [jev] попытка 1: <диагноз>
  ...
```
Последние 6 комментариев. Следующий исполнитель видит, на чём споткнулись.

### 10. Выбор раннера по ПРОВАЙДЕРУ

| Провайдер | Раннер |
|---|---|
| `anthropic` | `claude` CLI, `--permission-mode acceptEdits` |
| `openai` | `codex exec -s workspace-write` |
| `antigravity`, `openrouter`, `google`, `deepseek` | HTTP-шлюз |

Имя модели НЕ учитывается. Для составных (`NVIDIA/OpenRouter`) — приоритет последнего звена.

**Все раннеры добавляют в промпт требование прогнать тесты** (`_test_hint`), иначе гейткипер отклонит.

### 11. Запуск

- **CLI:** `subprocess.run(...)` в папке задачи, таймаут 1800 с, вывод + `git status/diff`
- **HTTP:** модель правит файлы по описанию (файлы передаются в контекст)

Возврат: `{'ok': bool, 'output': str, 'evidence': {changed, diffstat}}`

### 12. Приёмка

```
passed = result['ok']
   ├─ False → diagnose_failure(output, stage) → диагноз
   │            «<cause> → <action> (уверенность X)»
   └─ True  → gatekeeper_review(task, worker, output, passed)
                 → verdict: approve | reject | escalate_to_human
```

Гейткипер оценивает **свидетельство**: вывод + реальные git-изменения.
Механика: `approve` только если exit ok И работа соответствует заголовку И тесты прогнаны.

### 13. Закрытие / возврат

| Вердикт | Что происходит |
|---|---|
| `approve` | `complete` — задача уходит из очереди, воркер освобождается |
| `escalate_to_human` | ручная приёмка, задача остаётся |
| `reject` / `not passed` | `failAttempt` — попытка +1, диагноз в тред |

**Правило:** задача без прогона тестов **отклоняется**, даже если код верный.

## Кадры

**Кто в офисе:**
- `w0` Гермес — координатор, **исключён из автоназначения**
- ядро (не увольняются): фулстак, приёмщик, дизайнер
- нанятые под задачу: увольняются автоматически, когда работа кончилась

**Триаж Jev** выбирает исполнителя из **реального состава**, а не из абстрактных ролей.

## Отказы и защита

| Что защищено | Чем |
|---|---|
| Дубли планов | флаг `decomposed` ставится ДО вызова Jev |
| Молчаливое закрытие не того | гейткипер по свидетельству, не по returncode |
| Задача без тестов | требование прогона в промпте + проверка гейткипером |
| Рассинхрон журнала | `verify_journal` каждый тик |
| Два воркера в одной зоне | `busy_zones` |
| Работа до готовности предков | `deps_ready` |
| Потеря контекста ошибок | тред комментариев в промпт исполнителя |

## Где узкие места

1. **Часть решений Jev — секунды** (5–10 с), тик последовательный: `tick()` блокируется на `subprocess.run` до 1800 с. Одна длинная задача задерживает весь цикл.
2. **Инфраструктурные ошибки** (не тот каталог, не git-репо) Jev диагностирует как `agent_stale` — формально верно, практически бесполезно.
3. **HTTP-раннер** не даёт модели инструментов: годится для новых файлов, плохо для правки существующих.
4. **Гейткипер обрывался на 400 токенах** (исправлено: 1500) — 29% вердиктов не выносились.
