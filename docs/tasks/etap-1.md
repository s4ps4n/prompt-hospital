## Что сделать

Реализовать **слой журнала и операций** — ядро приложения, от которого зависит всё остальное.
Только TypeScript, без UI. Тесты — Vitest.

## Требования к данным (точно по спеке)

- Журнал: `j = { workers, queue, log, seq }`.
- `worker`: `{id, model, name, provider, role, color, status: run|done|blocked|wait, task: taskId|null, doneCount, history[]}`.
  `w0` — Гермес (координатор, роль закреплена, не удаляется).
- `task`: `{id, title, priority: 3|2|1, order, assignedTo: workerId|null, kind: role|null}`.
- `CATALOG` — 8 моделей: `{model, name, provider, hair, color, skin, style, acc}`.

## Требования к операциям

Все мутации — через чистые функции `OPS[name](journal, args)`, возвращают `{msg} | {err} | {noop}`.

Операции: `assign, reassign, unassign, setRole, setPriority, reorder, complete, block, addWorker, removeWorker, addTask`.

- Обёртка `run(name, args)` — клонирует журнал → применяет операцию → пишет в `log` → сохраняет (localStorage).
- `check(name, args)` — «сухой прогон»: возвращает, что операция сделает, БЕЗ изменения журнала (для валидации до анимации).
- Отрисовка — чистая функция от журнала (на этом этапе просто экспортируй селекторы/сортировку).

## Инварианты (обязательны)

- `task != null` ⇔ статус `run|blocked`.
- Очередь модели = задачи с `assignedTo = w.id`, кроме текущей.
- Сортировка очередей производная: `priority desc, order asc`.

## Правила поведения (по спеке, реализовать в OPS)

- assign на свободную модель → задача становится текущей, статус `run`.
- assign на занятую → задача встаёт в её очередь, текущая не прерывается.
- unassign → задача в лоток Гермеса (`assignedTo = null`).
- reassign → с одной модели на другую.
- setRole → только у свободной модели (статус `wait|done`); у занятой → `{err}`.
- setPriority → меняет `priority`, очередь пересортировывается.
- reorder → задача встаёт перед целью в лотке/очереди (по приоритету цели).
- complete → в `history`, `doneCount++`, берётся следующая из очереди (по приоритету), иначе статус `done`.
- block → статус `blocked`, задача остаётся текущей.
- addWorker → новый worker из CATALOG + роль. removeWorker → только без текущей задачи и очереди.
- addTask → в лоток (`assignedTo = null`).
- `task.kind` не совпал с ролью модели → assign/reassign даёт `{err}` с сообщением.

## Тесты (Vitest) — обязательны, на КАЖДУЮ операцию

Минимум:
1. assign на свободную → run.
2. assign на занятую → очередь (текущая не меняется).
3. unassign → в лоток.
4. setRole свободной → ок; занятой → err.
5. setPriority → сортировка меняется.
6. reorder → правильный порядок.
7. complete с очередью → берётся следующая; без очереди → done, doneCount++.
8. block → blocked, задача текущая.
9. addWorker / removeWorker (свободной ок, занятой err).
10. addTask → в лоток.
11. task.kind не совпадает с ролью → err.
12. Инвариант: после каждой операции `task != null` ⇔ `run|blocked`.
13. Чистота: `OPS[name]` не мутирует входной журнал (иммутабельность).

## Установка и запуск

- `npm install -D vitest` (если нет).
- Тесты: `npx vitest run`.
- Прогон должен быть зелёным.

## Правила качества (от координатора)

- Типы строгие (без `any`), чистые функции, читаемые имена.
- Никаких внешних библиотек для логики (только vitest как devDependency).
- localStorage оборачивается так, чтобы работало и без браузера (для тестов — in-memory fallback).
