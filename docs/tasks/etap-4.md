## Что сделать

Собрать всё приложение: связать журнал (этап 1), сцену (этап 2) и персонажей (этап 3) в рабочий UI.

## Компоновка (по README «Экран»)

- **Верх:** название «Prompt Hospital», счётчики статусов (run/done/blocked/wait), кнопки
  ＋Модель, зум −/Вписать/＋ (на этом этапе зум — заглушки, реальный зум в этапе 7),
  Журнал (JSON-дамп), Сброс.
- **Слева:** «Лоток Гермеса» (250px) — список конвертов с ▲▼ (reorder) и формой новой задачи
  (название, приоритет, роль).
- **Центр:** сцена `OfficeScene` (клик по комнате → карточка).
- **Справа:** карточка персонажа (по клику, 290px) — аватар, провайдер, статус, роль (select),
  текущая задача (Завершить / Блок / В лоток), очередь модели (▲▼↩), выполнено + история,
  «＋ Экземпляр с другой ролью», «Убрать из офиса».
- **Модалка каталога:** сетка моделей (из CATALOG) + выбор роли → addWorker.
- **Низ:** строка сообщений/ошибок — текст из `OpResult.msg` / `OpResult.err`.

## Интерактив

- Всё управление — через `store.run(name, args)` и `store.subscribe` (журнал — источник истины).
- Drag-and-drop (мышь): pointer events, порог 5px (иначе клик), призрак следует за курсором,
  подсветка цели, `elementFromPoint` → ближайший `[data-drop]` (id worker'а или `queue`).
- Drop на свободную модель → assign; на занятую → в очередь; на Гермеса/лоток → unassign;
  на конверт в лотке → reorder.
- Смена роли: select в карточке, у занятой модели заблокирован + тряска и подсказка (см. README).
- Удаление модели — только свободной; иначе сообщение об ошибке.

## Требования

- Отрисовка — функция от журнала. Нет локального состояния, дублирующего журнал.
- Типы строгие, без `any`. Тесты (Vitest + testing-library, поставь `@testing-library/react` если нужно):
  - клик по комнате → карточка; assign через UI → статус run;
  - drop на занятую → очередь; смена роли занятой → ошибка;
  - addTask через форму → в лоток; removeWorker занятой → ошибка.
- Линт 0 ошибок, сборка зелёная.
