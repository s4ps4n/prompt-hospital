# Этап B: офис читает реальный журнал оркестратора

Ты работаешь в репозитории Prompt Hospital (`/home/hermes/prompt-hospital`).

## Цель

Сейчас офис рендерит захардкоженное состояние из `src/journal/initial.ts` (localStorage).
Нужно, чтобы он читал **реальный журнал оркестратора** через API.

API уже готов и работает на `http://127.0.0.1:8090`:
- `GET /journal` → `{ workers, queue, log, seq }` (структура совпадает с `Journal` из `src/journal/types.ts`).
- `GET /health` → `{ok:true}`.
- `POST /op` → `{name, args}` (операции; для уровня B не обязателен).

## Что сделать

1. Добавить в store возможность **загрузки журнала с сервера**:
   - при старте приложения — `fetch('/journal')`, если доступно, использовать полученный журнал
     вместо `initial.ts`;
   - если `/journal` недоступен (офлайн, dev без API) — тихий fallback на `initial.ts`.

2. Уровень B — это **монитор**: офис показывает реальное состояние, но drag-and-drop
   **не пишет** обратно в реальный журнал (это уровень C). Поэтому:
   - либо оставить drag-and-drop локальным (меняет только отображаемое), либо задизейблить —
     реши по смыслу и отметь в докладе;
   - главное — при загрузке офис показывает реальные workers/status/tasks из `/journal`.

3. Убедись, что `Journal` из `types.ts` принимает JSON из `/journal` без преобразований
   (поля совпадают: `workers[].id/model/name/provider/role/status/task/doneCount/history`,
   `queue[].id/title/priority/order/assignedTo/kind`, `log`, `seq`). Если где-то тип не сходится —
   поправь с минимальными изменениями.

## Тестирование

- Сделай так, чтобы можно было включить remote-режим (например, env `VITE_JOURNAL_URL` или
  проп), и напиши тест: при подмене `fetch` офис рендерит workers/tasks из ответа `/journal`,
  а не из `initial.ts`. Fallback при ошибке — тоже тест.
- `npm run build`, `npx vitest run`, `npm run lint` — зелёные.
