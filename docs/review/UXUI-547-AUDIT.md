# UX/UI аудит реализации Split-screen редактора разделов (#547)

**Исполнитель:** Gemini Design (`w18`, `google/gemini-2.5-flash` via Antigravity)  
**Роль:** Дизайнер (скилы: `web-design-guidelines`, `ui-ux-pro-max`)  
**Объект аудита:** Редактор контента страниц Каркас CMS (двухколоночный режим)  
**Дата:** 29 сентября 2026  

---

## 1. Эргономика рабочего пространства и расположение элементов
* **Зона разделения (Divider):** Требуется наличие активной зоны захвата (hit area) шириной не менее 8px для изменения пропорций панелей. Визуальный индикатор (handle) должен менять состояние при наведении (hover) и активном перетаскивании.
* **Иерархия:** Левая панель (навигация/структура) должна иметь фиксированную ширину или минимальный порог сжатия (`min(520px, 40%)`), чтобы не нарушать читаемость контента. Правая панель (редактирование и живой сайт) должна быть приоритетной по ширине при ресайзе.
* **Контекст:** При переключении фокуса между панелями необходимо визуальное подтверждение активной области (изменение цвета границы или легкое затемнение неактивной панели), чтобы минимизировать когнитивную нагрузку при работе с горячими клавишами.

---

## 2. Оценка контраста, отступов и типографики
* **Типографика:** В редакторе кода/контента необходимо использование моноширинного шрифта (согласно токенам `font-family-mono`) для обеспечения выравнивания. Размер шрифта должен соответствовать `text-sm` (13–14px) для плотных интерфейсов.
* **Контраст:** Коэффициент контрастности текста относительно фона должен соответствовать стандарту WCAG AA (минимум 4.5:1 для основного текста). Особое внимание уделить цветам синтаксиса — они не должны сливаться с фоном при любом режиме (Light/Dark).
* **Отступы:** Использование сетки 4px (spacing scale). Внутренние отступы (padding) в панелях должны быть не менее 16px для предотвращения «прилипания» контента к краям контейнера.

---

## 3. Поведение на разных брейкпоинтах
* **Desktop (>= 1024px):** Split-screen является основным режимом. Обязательна поддержка независимого скролла колонок и фиксации панели действий.
* **Tablet (768px – 1023px):** Рекомендуется переход на вертикальное стекирование (Stacking) или использование табов (Tabs) для переключения между панелями. Горизонтальный скролл в Split-screen на планшетах недопустим.
* **Mobile (< 768px):** Split-screen невозможен. Реализация должна принудительно переключаться в одноколоночный режим с навигацией через таб-бар или модальное окно.

---

## 4. Рекомендации и вердикт

**Статус:** `Conditional Pass` (Условное одобрение)

**Требования для перехода в статус Ready:**
1. **Проверка адаптивности:** Подтвердить, что на мобильных устройствах Split-screen трансформируется в одноколоночную структуру (`< 1100px` в коде Claude Code уже заложено).
2. **Accessibility:** Убедиться, что навигация между панелями доступна через клавиатуру (`Tab` / `Shift+Tab`) и фокус-кольца (`focus rings`) соответствуют дизайн-системе Каркаса.
3. **Производительность:** Убедиться, что ресайз панелей через `ResizeObserver` не вызывает лагов при отрисовке (отсутствие layout thrashing).
